# 调研可复现性与证据谱系

## 一、为什么“有链接”还不够

一个技术结论即使附有链接，仍可能缺少三个关键问题的答案：链接中的哪一段支持它、经过了什么转换、由谁或哪个 Agent 作出了筛选和判断。AI 加速搜索与摘要后，这些中间步骤更容易被压扁成一段流畅答案。

可复现不要求另一位研究者得到逐字相同的回答，而是让他能够重建关键路径：用什么问题、在什么时间和范围搜索，哪些材料被纳入或排除，结论如何从来源转化而来，最后由什么验证裁决。

## 二、三个可迁移的成熟框架

### 1. W3C PROV：把谱系拆成 Entity、Activity、Agent

[W3C PROV-O](https://www.w3.org/TR/prov-o/) 用三类起点概念描述 provenance：

- **Entity**：来源页面、源码版本、转写、资料卡、结论、截图；
- **Activity**：搜索、筛选、转写、摘要、比对、运行测试；
- **Agent**：人、模型、脚本、浏览器或对结果负责的团队角色。

它还区分 `wasDerivedFrom`、`wasQuotedFrom`、`wasRevisionOf` 与 `hadPrimarySource` 等关系。对本项目最有价值的不是引入 RDF，而是获得一套精确语言：总结不是来源，引用不是推导，修订不是独立证据，执行动作也需要责任主体。

### 2. PRISMA-S：让检索过程可以被别人重跑

[PRISMA-S](https://doi.org/10.1186/s13643-020-01542-z) 是系统综述检索报告指南。它的 16 项检查覆盖数据库与平台、完整检索式、限制条件、检索日期、灰色文献、补充搜索、去重和更新等信息。

技术调研不需要假装成系统综述，但可以借用一个轻量搜索日志：

| 字段 | 技术调研中的写法 |
|---|---|
| 问题 | 这轮搜索要填哪个决策缺口 |
| 渠道/平台 | 官方文档、GitHub Code、Issue、论文库、视频平台 |
| 查询 | 保留关键搜索式、限定符和版本词 |
| 时间与范围 | 搜索日期、版本、语言、时间窗 |
| 命中与筛选 | 候选数、纳入/排除理由、去重方式 |
| 追溯搜索 | 从引用、作者、commit、Issue 继续滚雪球 |

必须保留原指南自己的边界：PRISMA-S 明确说它用于透明报告，不是搜索质量评价工具。**过程可复现与结论可信是两道门禁。**

### 3. Deep Research Bench：把报告质量与引用质量分开

[DeepResearch Bench](https://arxiv.org/abs/2506.11763) 用 100 个跨 22 个领域的任务评估 Deep Research Agent，并把评价拆成报告质量与信息搜集/引用两部分。其 FACT 框架同时观察有效引用数量与引用准确性；实验结果也显示“引用更多”和“引用更准确”并不总是同步。

这给日常调研一个直接启发：不能用链接数量替代覆盖度，也不能用覆盖度替代 entailment。资料库至少要分别回答：

1. 重要主张是否都有证据；
2. 每条证据是否真的支持相邻主张；
3. 报告是否回答了原始决策问题。

## 三、轻量证据谱系

每条高影响主张可以保存为一个六节点链：

```text
决策问题
  → 查询/定位动作
  → 原始来源与版本
  → 可定位证据片段
  → 推断或转换规则
  → 验证结果与最终表述
```

建议再附四个字段：执行者、时间、置信度、证据上限。这样既能画知识图谱，也能只用 Markdown 和 Git 维护。

当前仓库已经自然对应这套模型：

| 本项目资产 | 谱系角色 |
|---|---|
| Research Brief、gap matrix | 决策问题与待填槽位 |
| bookmarks、来源卡 | 来源 Entity 与筛选记录 |
| evidence slices | 来源到演讲主张的转换说明 |
| claim ledger | 主张—来源—边界关系 |
| 运行截图、测试 JSON | 验证 Activity 的输出 |
| Git commit | 修订关系、作者与时间 |

## 四、案例如何上台

### Deck.gl

失败现象 → API/版本问题树 → 官方文档与 9.1.12 源码 → 四个隔离实验 → 浏览器 JSON/截图 → “证据升级让问题收敛”。具体 accessor 名称只留在证据页。

### 视频转知识

当前案例恰好展示谱系断裂：候选表和最终总结存在，但原始音频、逐字转写和中间日志缺失，所以不能把流程回忆写成完整可复核事实。缺失本身是很好的教学证据。

### WPS

开源项目、相邻 API、运行时反证和最终 adapter 是不同实体；“参考了什么”与“最终复制了什么”必须分开。这样才能准确解释“不重复造轮子”是复用认知资产，而非整仓照搬。

## 五、演讲可用结论

1. **不要只保存答案，要保存答案的生产关系。**
2. **搜索日志解决可重跑，主张审计解决是否被证据支持，运行实验解决是否在目标环境成立。**
3. **成熟标准可轻量借用，不必把日常技术调研包装成学术系统综述。**
4. **谱系的最小单位不是链接，而是“主张—片段—转换—验证”。**
5. **完整记录不保证正确，但没有记录时，错误很难被定位和纠正。**

推荐度：A。适合作为方法论后半段的一页，把资料卡、主张账本、证据切片和 Git 从“文档习惯”提升为有理论依据的 provenance 设计；完整字段和标准术语留在附录。

## 六、边界

- W3C PROV 是通用 provenance 标准，不是 AI 调研质量标准；本节属于方法迁移。
- PRISMA-S 面向系统综述的检索报告，日常技术调研只借其透明性字段，不宣称达到系统综述完备性。
- DeepResearch Bench 是 2025 年的研究基准，商业系统会变化；引用具体模型成绩时必须按论文测试时间和设置表述。
- 本项目尚未做“有/无谱系记录”的效率对照，因此不宣称它必然节省多少时间。
