# 案例：从一张 B747 舱位图找到可建模的货舱约束

> 归档于 2026-09-19。本案例只分析项目文档，不读取或评价实现代码。它展示的是一次资料检索如何从图片中的陌生代码，逐步进入航空货运的专业术语和原始资料层；文中的几何结论仍受公开资料边界限制，不能替代承运人的正式装载手册。

## 案例背景

新需求不是制作一架外观相似的飞机，而是为 B747-400F 三维货物分配建立可计算的舱位轮廓。需要回答的问题包括：顺丰公开舱位图中的 `LR / LL / PL / QR / 11P` 分别是什么位置；每个位置允许什么 ULD 或 build-up contour；顶部从哪里开始收口；左右舱位是否需要镜像；哪些公开数据足以进入 3D 预判，哪些仍须等待正式 Weight & Balance / Cargo Loading Manual。

直接搜索“B747-400F 每个货舱尺寸”只能得到整机运力、舱门尺寸和货代汇总，无法回答具体舱位的几何约束。真正的突破来自顺丰舱位图本身。

## 最值得讲的检索转折

### 1. 不先搜索问题，先从图片抄出行业语言

舱位图上出现了大量低频字符串：

```text
A1 / A2 / B1
CR / CL / LR / LL / PR / PL / QR / QL
11P / 12P / 21P / 22P / 23P
SIZE CODES A, M & N
```

这些代码比“747 货舱”更有区分度。把机型和多个低频代码组合，例如：

```text
"B747-400F" "LR" "LL" "PL"
```

可以显著减少宣传页和通用参数页，进入讨论 cargo position、pallet contour 和 loading configuration 的资料层。这一步说明：**图片不仅是视觉参考，也可能是专业检索词的来源。**

### 2. 搜索结果不是答案，而是下一轮术语生成器

第一轮资料暴露了 `PA1 / PA2 / PMD / H4M / HPL / PEB` 等 contour code。它们短、罕见、出现在代码栏并与具体位置对应，因此值得单独锁定：

```text
"B747-400F" "H4M" "HPL" "PA1" "PA2"
```

这最终定位到中国货运航空的 B747-400F/400ERF 设备说明。它提供的结构不再只是“货舱多大”，而是：

```text
Position → Contour Code → Geometry / Size
```

它能把顺丰图中的位置代码转成建模可用的轮廓类型：例如 A1 对应 PA1，A2/B1/C/D 主要对应 PMD，E–T 的多数高板位对应 H4M，PL 使用单独的 HPL，Q 使用 PEB。

### 3. 用罕见数字形成“数值指纹”

专业资料中的数字也成为下一轮检索入口，例如：

```text
"HPL" "2.87" 747-400F
"PA1" "1.55" "1.22" 747-400F
"H4M" "3.18" "2.44"
```

`2.87`、`1.55 + 1.22` 这样的组合，比“747 cargo height”更接近唯一指纹。它适用于机械规格、标准、法规、零部件和论文中的固定参数检索。方法的重点不是背数字，而是发现**一份可信资料中的罕见数值可以反向定位同一技术体系的其他材料**。

### 4. 遇到编号冲突，不急着压成统一答案

顺丰后下货舱图出现 `31–45`，其他资料则出现 `31P / 32P / 41P / 42P`，或更细的 `43L / 43R`。继续搜索后发现，编号与可用位置会随 ULD configuration 改变。因此资料没有被强行整理成“八个固定 PMC 位”，而是保留“按配置模式建模”的结论。

同样，公开资料对 Q 位 PEB 的允许高度存在运营口径差异；Bulk 也只有容积与门尺寸，缺少精确 station contour。这些都被留为 `待确认`，而不是让 AI 补齐一个看起来完整的三维包络。

## 来源如何分工

| 来源 | 本次承担的职责 | 不能承担的职责 |
|---|---|---|
| 顺丰航空公开舱位图 | 确认 M 编号、position code、主/下货舱布局和图中标注 | 没有直接给出每个位置的详细 contour 折点 |
| 中国货运航空设备说明 | 提供 PA1、PA2、PMD、H4M、HPL、PEB 的位置映射和主要尺寸 | 不能自动代表顺丰自己的最终承运限制 |
| B747-400 Cargo Handling Manual 公开副本 | 补充下货舱 Size Code 与 configuration | 公开副本的来源、版本和适用范围仍需记录 |
| Qantas、其他运营商和论文图 | 交叉核对高度级别、PEB、门与配置关系 | 二手收录不能升级成制造商或顺丰正式批准资料 |
| 几何推断 | 把左右高板解释为外侧削角的镜像 envelope | CKair 纯文字没有直接给出所有单侧折点；认证级模型仍需正式 contour 图 |

这里没有一个来源能单独回答全部问题。资料组合得到的是**建模和装载预判约束**，不是承运批准。正式装载仍应服从顺丰内部 W&B / Cargo Loading Manual。

## 从资料到可执行资产

检索没有停在长篇总结，而是落成“舱位 → 类型 → 几何 → 置信度”的结构，例如：

```json
{
  "position": "M11",
  "code": "LR",
  "deck": "main",
  "contour": "H4M",
  "base_m": [3.18, 2.44],
  "max_height_m": 3.00,
  "taper_start_height_m": 2.44,
  "taper_m": 0.78,
  "side": "R",
  "mirror_group": "LR_LL",
  "confidence": "mapping high; exact fold points require approved drawing"
}
```

这个结构把“直接来源”和“工程近似”同时带到下游：算法可以先用公开 envelope 做碰撞预判，界面可以展示置信度，而正式资料到达后仍能替换精确折点。它体现了本演讲的核心：AI 调研的产物不只是答案，而是带来源和边界、能够进入下一步工作的资源。

## 失败与边界值得保留

- `L/R` 不能直接解释成同一仓位的左右版本，也不能把 LR/LL 想象成 PA1 被切成两半；必须追到 contour 体系。
- ULD 的物理标准尺寸与某运营商在某位置允许的 build-up 高度不是一回事。
- 搜索摘要会丢失表头、适用位置、图片轮廓和条件注释；必须进入网页正文、PDF 页面和原图。
- 多运营商资料可以帮助发现结构与冲突，但不能凭相似机型直接替代顺丰规则。
- H4M/HPL 的左右镜像是由双列舱位、图形和机身外侧约束共同形成的中高置信解释；精确单侧折点仍需正式图纸。
- Bulk 精确边界、PL 局部 forbidden volume、鼻部沿 station 的变化、floor load 和累计区域重量仍未闭环。

## 演讲中的推荐角色

这是一个很强的“AI 如何搜索”案例，适合替代抽象的关键词技巧罗列，控制在 2–3 页：

1. **一张图里真正有价值的不是飞机，而是 `LR / LL / PL / 11P` 这些陌生代码。**
2. **低频共现词 → 行业术语 → 数值指纹 → 原始手册**，用一条检索路径展示查询如何逐轮收窄。
3. **公开资料 → 可计算 envelope + 置信度 + 待确认清单**，展示结构化整理怎样进入产品与算法需求。

面向产品经理时，可以把问题表述为：“不是能不能找到一个尺寸，而是这个尺寸属于哪个运营商、哪个配置、能支持到哪种产品决策。”不需要展示全部舱位表和 3D 代码。

演说推荐度：**A**。它与飞机建模案例互补：前者从业务事实和图片参考生成宣传模型；本案例从图片代码追到专业装载资料，生成计算约束。正式版是否进入主体，应与 Web Excel、WPS 的篇幅一起取舍。
