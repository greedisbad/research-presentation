## 回答的问题

技术调研如何跨会话保存，并转化为后续 Agent 可消费的计划、任务和验收上下文？

## 可用证据

- 三阶段持续保存研究、设计、计划、实施、验证和交接记录。
- 真实资产先通过单角色纵向切片验证，再批量扩展，并保留 fallback。
- 复盘显式记录已确定决策、不要重复的调研、优先风险和浪费路径。
- 子任务使用边界明确的 task brief，而不是依赖完整聊天上下文。
- 评审曾因漏读测试文件产生误报；主线程使用文件、diff 和测试输出裁决，同时接受同轮有证据的真实问题。
- 单元测试之外，真实桌面与移动端观察发现了遮挡等视觉问题。

## 可执行信息

- `LEARNINGS.md` 分为已确认、已排除、待验证三类。
- 搜索收敛后先做最高风险纵向切片。
- 任务 brief 固定目标、非目标、文件边界、接口、证据和验收命令。
- 评审结论使用 Accept / Reject / Defer 证据裁决。

## 演示用法

只作为 2–3 分钟短案例，讲负知识、风险切片和任务交接；不解释游戏代码和业务规则。
