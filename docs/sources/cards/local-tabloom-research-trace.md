## 回答的问题

AI Agent 如何在一个完整工程周期中识别信息缺口、路由到不同证据源、利用错误和真实边界修正判断，并把结论固化为可审计产物？

## 可用证据

- 16 个阶段逐项记录待决策、期待信息、实际来源、决策与可验证产物。
- 明确区分用户、模型通用知识、官方文档、代码、运行、Git 和 Skill。
- 提交历史支持原型、设计、计划、实现、缺陷修复、live harness 和复盘的时间顺序。
- 动态导入、空组与非 Thinking 三个问题展示了不同来源如何改变实现。
- 文档自身经过无上下文读者测试，并记录由此补充的歧义与边界。

## 可执行信息

- 先写信息缺口，再生成搜索式。
- 根据问题所属层选择用户、官方文档、源码、运行或版本证据。
- 用固定假数据的真实实验裁决 mock 无法回答的问题。
- 记录证据前后置信度和行动变化，而不追求保存隐藏思维过程。
- 把失败路线、测试、ADR、Skill 和发布核验作为研究产物。

## 局限

- 阶段 1–15 主要为事后重建，不是完整实时日志。
- 部分历史搜索式、网页访问和工具输出没有保存。
- 单项目不能证明普遍效率提升。
- 模型与 Chrome 的版本化事实必须在正式引用前重查。
- Git 能支持发生顺序和变更范围，不能还原所有动机。
