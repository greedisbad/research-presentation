# 长版故事板逐页制作规格

## 字段说明

本文件是 [`30-完整长版故事板.md`](30-完整长版故事板.md) 的制作层。每页都必须只有一个 takeaway；转场说明下一页为什么必然出现，而不是一句空泛串词。

展示档位：

- **Live**：现场操作能显著增加可信度，且已有可控输入；必须同时准备 Snapshot 降级；
- **Snapshot**：真实截图、运行报告、文件裁切或录屏；优先承担案例事实；
- **Static**：重画的概念图、流程、表格或大字；不能伪装成运行证据。

必要性：

- **Core**：长版和未来现场版默认保留其判断；
- **Support**：支撑理解，可并入相邻页；
- **Optional**：独立价值存在，但现场版优先移备注或附录。

证据强度沿用资料库口径。这里的“高”表示限定后的页内表述已有直接支持，不表示方法具有普遍因果效果。

## 正文与附录边界

### 正文只保留的技术细节

- 能形成认知转折的一个具体错误：`2025 → 2005`；
- 能显示版本意识的一个 tag：Deck.gl `v9.1.12`；
- 能显示结构下沉的三个名词：Theme、SlideSpec、adapter；
- 能显示动态证据的少量字段：帧推进、像素变化、picking；
- 能显示状态纪律的三栏：Confirmed、Rejected、Unverified。

### 默认移入讲者备注或附录

- Deck.gl accessor、degree/radian 计算位置、uniform block 语法；
- WPS 类名、工具名、对象 API、测试文件与完整依赖版本；
- Dice 游戏规则、角色、美术与完整测试数量；
- Chrome API 枚举、权限字段、具体模型参数；
- ASR 下载命令、音频编码参数、完整转写；
- 运行报告全部字段、哈希和逐文件行号；
- D03 多路线完整决策矩阵、P01 谱系审计总表。

这些细节不会从资料库删除。问答出现版本、实现和证据质疑时，直接从附录或源文件回读。

| Live 候选 | 主方案 | 必备降级 | 当前状态 |

## 后续压缩的优先顺序

压缩时先合并表达，不先删除证据：

1. 合并 01–02、04–05、06–08；
2. 合并 11–12、15–17、18–20、21–22；
3. 合并 24–25、28–29、30–31；
4. 合并 32–34、36–37，39 和 40 可移附录；
5. 合并 43–46；
6. 合并 47–50；
7. 合并 51–52、54–55。

即使合并，也必须保留五个不可删除的主转折：

```text
模糊请求 → 决策与信息缺口
候选项目 → 当前约束筛选 → 可执行资产
不可搜索视频 → 候选语料 → 核验边界
失败生成 → 文档/同版本源码/实验
一次结论 → 可交接、可复用的项目记忆
```

## 制作前门禁

- 55 页均有一个且只有一个主要判断；
- 55 页均有 takeaway、下一页转场、展示档位、证据强度、必要性和压缩方式；
- 所有 Live 候选均有 Snapshot 降级；
- WPS 真机完成前，任何页面不得写成已通过宿主验收；
- 具体 API 和长代码已有附录去向；
- 下一步可以直接选择演示载体并制作完整第一版，无需重新决定内容结构。
