# 信息觅食与 Sensemaking：为什么技术调研不是“搜完再总结”

## 核心判断

技术调研更接近两个相互作用的循环，而不是一条固定流水线：

```text
觅食循环：搜索 → 扫描 → 筛选 → 摘取 → 建立证据文件
理解循环：组织 → 假设 → 找冲突 → 改写框架 → 形成结论
                     ↑                  ↓
                     └──── 重新定向搜索 ────┘
```

Peter Pirolli 与 Stuart Card 对情报分析员的认知任务研究，把分析过程概括为一组围绕信息搜寻的活动和一组围绕意义建构的活动，两者之间存在大量往返。信息从外部数据源逐步进入“证据文件”，再被组织为 schema、假设与最终产物。[Pirolli & Card 2005 原论文](https://www.researchgate.net/profile/Peter-Pirolli/publication/215439203_The_sensemaking_process_and_leverage_points_for_analyst_technology_as_identified_through_cognitive_task_analysis/links/02bfe50f09ca94efc0000000/The-sensemaking-process-and-leverage-points-for-analyst-technology-as-identified-through-cognitive-task-analysis.pdf)

这项研究讨论的是情报分析，而不是 AI 技术调研。本文借用的是过程结构：收集证据和形成解释不能彻底分开；中间发现会改变后续检索。

## 一、搜到资料不等于形成知识

Pirolli 与 Card 给出一个简洁的转换：

```text
Information → Schema → Insight → Product
```

其中最容易被“AI 总结”掩盖的是 Schema：同一批事实需要被重新表示为适合当前问题的结构，才能支持比较、推理和行动。如果只把十篇网页分别压缩成十段摘要，信息变短了，但未必形成了能回答问题的表示。

对应到本项目：

- `bookmarks.md` 是候选池，不是结论；
- 来源卡把不同媒介整理到统一字段；
- claim ledger 把主张与证据连接起来；
- gap matrix 把残留、冲突和下一次查询暴露出来；
- 案例文档把证据重新组织为可以解释的方法。

因此，“结构化整理”并非排版工作，而是调研中最重要的认知步骤之一。

## 二、残留不是垃圾，而是下一轮搜索的导航

论文描述的 learning loop complex 包含表示生成、数据覆盖和表示转换：当材料无法装入当前框架时，会出现 residue；这些不匹配项会促使分析员调整表示。

技术调研中的 residue 可能是：

- 两份官方文档对同一能力描述不同；
- README 宣称支持，但目标版本源码没有对应入口；
- AI 给出的 API 名称看似合理，实际运行失败；
- 一个高星项目没有许可证或最近发布；
- 视频中的经验结论找不到外部证据。

低质量流程会删除这些“不整齐”的材料；高质量流程会把它们转成下一轮查询：

| 残留 | 下一步定向动作 |
|---|---|
| 版本描述冲突 | 限定版本查 changelog、tag、blame |
| 文档有能力、示例无入口 | 查同仓库调用点和最小运行实验 |
| 只有二手结论 | 追作者、论文、标准或原始数据 |
| 多个方案都声称可用 | 先定义判据，再做同条件对照 |
| 摘要无法支持原子主张 | 回到原文定位段落，或降低结论强度 |

## 三、AI 应该接手什么

AI 擅长降低两个循环之间的切换成本：

- 扩展同义词、实体名、错误信息和版本限定词；
- 扫描候选池并按统一字段初筛；
- 从原文提取能支持具体主张的证据；
- 建立实体、版本、文件、Issue、PR 与实验之间的关系；
- 找出未被当前结构覆盖的材料；
- 根据 gap matrix 生成下一轮小范围查询。

人仍负责：

- 决定研究要支持什么工程决策；
- 判断哪些来源和冲突具有后果；
- 接受或拒绝新的解释框架；
- 决定何时证据足够、可以停止；
- 对采用方案和发布结论负责。

## 四、可复制的双循环协议

### 循环 A：Information Foraging

1. 写一个可回答、可停止的研究问题。
2. 生成查询矩阵，而不是单个万能关键词。
3. 用标题、机构、日期、版本和摘要建立候选池。
4. 分层阅读，只把高价值来源推进到原文提取。
5. 将原始事实写入来源卡，不急于写总论。

### 循环 B：Sensemaking

1. 按“主张 / 方案 / 版本 / 风险 / 实验”重组证据。
2. 写出当前假设，并明确它是推断。
3. 搜索冲突、残留和无法归类的信息。
4. 必要时改变分类方式或拆分研究问题。
5. 产出能改变行动的决策、实现路线或验证实验。

### 每轮的停止记录

每轮不以“看了多少链接”结束，而记录：

- 哪些问题已有一手证据；
- 哪些结论仍是推断；
- 哪些冲突尚未解决；
- 新搜索是否仍会改变决策；
- 下一步应继续搜索、读源码还是做实验。

## 五、与三个本地案例的连接

### WPS：从候选池变成实现 schema

项目没有把十一个参考项目逐个做完摘要，而是按能力、集成方式和可迁移模式重新组织，最后映射到具体代码与测试。真正产出价值的是“参考资产 → 工程决策 → 实现证据”的表示。

### 视频：先把媒介转换成可觅食的证据池

下载、ASR 和清洗解决的是获取问题；查询矩阵、结构化字段和跨来源核验才进入意义建构。转写稿不是终点，只是从视频进入可检索证据层。

### Deck.gl：失败是触发 representation shift 的 residue

多个 HTML 都无法达到效果，说明“继续换提示词”这个框架覆盖不了事实。问题随后被重新表示为视角、图层 API、动画和目标版本源码等子问题，搜索才开始收敛。

## 六、推荐加入演说的点

推荐度：S，适合成为核心方法论的一页或两页。

最值得讲的不是术语，而是三个转变：

1. **搜索和理解必须往返**：好调研会根据中间证据改写问题。
2. **结构是推理工具**：资料卡和账本不是文书负担，而是把信息变成洞察的中间表示。
3. **失败材料是导航信号**：不匹配项决定下一轮应该查文档、源码、历史还是运行时。

可用讲法：

> AI 不只是替你跑得更快；它可以帮助你在“找材料”和“改模型”之间更快迭代。真正的自动化对象，是这两个循环之间的搬运、对齐和追踪。

## 七、证据边界

- Pirolli 与 Card 的 2005 论文基于有限的情报分析认知任务研究，作者也提醒不要从局部任务过度泛化。
- “双循环适用于 AI 技术调研”是本项目的方法迁移，不是论文直接验证的结论。
- 流程图表达概念关系，不代表每次研究都必须严格走完固定步骤。
- AI 能降低整理成本，不证明它能独立判断来源真实性或工程适用性。
