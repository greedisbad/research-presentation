# D01：Deck.gl 失败现象与问题重写

## 要支持的演讲主张

当 AI 连续生成的实现“看起来完整，但就是不工作”时，不要继续搜索整句现象或笼统地要求“再修一版”。先把现象改写成可分别证伪的对象边界、数据语义、生命周期、版本兼容和非功能约束问题。

## 失败现象不是可直接搜索的问题

原始现象可以简写为：

```text
用 AI 生成了多个 Deck.gl 图标旋转 HTML，
页面可以打开，但旋转效果没有达到预期。
```

这句描述混合了至少五类未知：

| 未知类型 | 可证伪的问题 | 应优先查什么 |
|---|---|---|
| 对象边界 | 当前直接创建的 Layer 究竟支持哪个 accessor？ | 当前 Layer 的官方 API、类型定义、源码 |
| 数据语义 | 旋转值是 degree 还是 radian？谁负责换算？ | 官方参数文档与同版本 shader |
| 生命周期 | 新 Layer 对象是重建 GPU 状态，还是按 `id` 复用？ | Layer lifecycle 文档与运行计数 |
| 版本兼容 | 某个 shader 写法在 9.1.12 是否仍可用？ | 目标版本同仓库已运行扩展实现 |
| 非功能约束 | 怎样证明在旋转、可 picking，且没有重复初始化其他层？ | 真实浏览器指标和自动化门禁 |

## 一句可迁移结论

> 失败现象不是搜索词；先把它改写成若干个可证伪的信息缺口。

## 证据边界

- 现有复盘是事后整理，不是全量实时操作日志。
- 没有原始生成 HTML 的版本历史，不把当前基线文件宣称为“原始失败现场”。
- 具体 accessor 和角度单位是证据细节，演讲主体应突出如何拆题。
- 这是单个工程案例，不能据此比较模型能力或证明普遍效率改善。
