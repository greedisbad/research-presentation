# W02：WPS 从提示约束升级到工具约束

## 要支持的演讲主张

调研结论不应只写进 Prompt。反复出现的行为约束应该下沉为工具 schema、代码校验或自动测试，使较轻量、缺少复杂 Skill/MCP 的 Agent 也能稳定复用。

## 失败信号

- 原文件：`tmp/wps-ai-plugin-main/.planning/phases/09-excel-word-agent/09-LEARNINGS.md`
- 第 50–55、161–165 行附近记录：Prompt 已要求批量操作，模型仍逐段调用格式工具。
- 60 个正文段落在单值接口下需要约 60 次工具调用。

这里能证明的是一次本地运行观察，不能外推为某个模型的普遍服从率。

## 结构性修复

- 当前代码：`tmp/wps-ai-plugin-main/wps-plugin-word/src/agent/tools.ts` 第 180–185 行附近。
- `getIndices()` 同时接受单个 `paragraphIndex` 与数组，过滤非法索引后统一返回数组。
- 对外工具仍保持语义清晰，但一次调用可以覆盖多个段落。

```text
Prompt：“请批量操作”
          ↓ 不稳定
Schema：paragraphIndex: number | number[]
          ↓
Executor：统一转成合法索引数组并循环执行
```

## 为什么属于技术调研

这不是单纯编码技巧。它完成了三次信息转化：

1. 从运行日志识别“自然语言约束没有稳定生效”；
2. 从多个 Agent 工具模式中抽象“批量能力属于接口职责”；
3. 将经验编码进 tool schema，使后续模型无需记住完整事故背景。

## 可展示的前后对比

| 层级 | 修改前 | 修改后 |
|---|---|---|
| 提示 | 要求“同类操作一次完成” | 仍保留意图说明 |
| 工具 | 一次一个段落 | 单个或数组都接受 |
| 执行 | 模型决定是否批量 | 代码负责规范化与循环 |
| 复用 | 依赖模型服从 | 更换较轻 Agent 仍有结构性能力 |

## 证据边界

- 下载包没有原始运行日志与调用计数快照，因此“60 次”来自 Learnings 对任务规模的记录，不是本轮重新测量。
- 当前代码能证明数组接口存在；本轮未安装依赖，也未重新运行工具单元测试。
- 不能由此断言“所有规则都应写成工具”。开放判断、审美和高后果决策仍应保留给人。
