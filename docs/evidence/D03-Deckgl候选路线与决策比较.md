# D03：Deck.gl 候选路线与决策比较

## 要支持的演讲主张

技术调研的产物不应只是一个“最佳答案”。当多条路线都可行时，AI 应把候选方案放进同一组约束、观测指标和决策标准中比较，再结合当前架构做选择。

## 为什么保留四条路线

- 路线 01–03 是三种可能的生产实现层级：局部逐帧状态、低频目标值与过渡、GPU uniform。
- 路线 04 不是生产候选，而是只改变单位这一个变量的诊断基线。
- 把诊断路线和生产路线分开，可以防止“能证明根因”被误写成“应该上生产”。

## 候选路线全量比较

| 路线 | 应用层更新方式 | 本次报告中的提交次数 | 优势 | 主要代价 | 角色 |
|---|---|---:|---|---|---|
| 01 CompositeLayer + `updateTriggers` | 内部每帧更新局部状态 | 315 | 符合当前 CompositeLayer 架构，不需全局重交 layers | 每帧仍有局部状态/属性工作 | 当前推荐集成路线 |
| 02 低频目标 + transition | 每两秒提交目标，中间帧插值 | 2 | 应用层提交频率低 | 连续衔接、暂停和角度累积需额外管理 | 低频更新候选 |
| 03 GPU shader uniform | JavaScript 每帧只更新 uniform | 0（页面记录的 layer/state submit） | 大量实例时扩展性潜力最高 | 依赖 shader module 内部范式，版本耦合与维护成本高 | 规模增长后候选 |
| 04 degree/radian 对照 | 同时运行错误与正确表达 | 319 | 只改一个变量，用于裁决单位假设 | 不是生产设计 | 诊断基线 |

提交次数来自 [`runtime-report.json`](runtime/deckgl/runtime-report.json) 中对约 5.2 秒运行的一次观测，不是性能基准，也不能直接互相换算为 CPU/GPU 成本。

## 共享的验收维度

| 维度 | 观测方式 | 可支持的最大主张 |
|---|---|---|
| 画面变化 | WebGL 局部像素签名持续变化 | 取样区域存在动态画面 |
| 对象身份 | `deckgl.pickObject(...)` 命中目标 | 变化区域有可拾取的 Deck.gl 对象 |
| 生命周期 | 静态参照层 `initializeState()` 计数为 1 | 本次运行没有反复初始化该参照层 |
| 运行健康 | 帧推进、Deck 错误、页面错误、功能资源错误和控制台 | 本次运行满足显式门禁 |
| 人工可观察性 | 暂停、单步 `+6°`、指标面板 | 可以人工复核高速动画，不只凭印象 |

像素变化不能单独证明变化来自预期图层，picking 也不能单独证明旋转是正确属性驱动。这些信号组合后增强结论，但仍需对主张边界保守。

## 决策如何从比较中得出

复盘的最终建议是先用路线 01，理由不是它在所有维度都“最优”，而是它与当前 `TyphoonLayer` 已是 CompositeLayer 的架构最匹配，改动面最小。只有当旋转实例增长到数千级，才考虑用路线 03 换取更高的扩展上限。

这是“局部最适”，而非“普遍最优”。

## 候选视觉素材

1. 四列候选卡：每列只显示更新位置、一个优势、一个代价和当前角色。
2. 提交次数 315 / 2 / 0 可作为观测差异，页脚必须标注“单次约 5.2 秒运行，非性能基准”。
3. 四张运行快照：[`01`](runtime/deckgl/01-update-triggers.png)、[`02`](runtime/deckgl/02-transitions.png)、[`03`](runtime/deckgl/03-shader-animation.png)、[`04`](runtime/deckgl/04-baseline-radians.png)。
4. 决策天平：当前架构匹配/改动小 ↔ 扩展上限/版本耦合。

## 候选讲述顺序

1. 先展示“都能转”，不立即宣布赢家。
2. 将路线 04 分离为诊断基线，避免与三条生产路线混比。
3. 用共享门禁说明比较前先保证基本正确性。
4. 再用侵入性、更新位置、版本耦合和适用规模做决策。
5. 以“选择与当前约束最匹配的路线”收束。

## 一句可迁移结论

> 先让多条候选路线在同一验收环境中变得可比，再选择与当前架构和风险最匹配的那一条。

## 证据边界

- 本次没有大规模实例压测，“GPU 路线扩展上限更高”是工程推断，不是当次 benchmark 结论。
- FPS 和 submit 计数来自单次、短时、特定环境快照，不能用来声称某路线普遍快多少。
- 四页的共享门禁不代表它们对现有 Vue 3 项目的集成成本已被实测。
- 路线 01 的推荐依赖“当前已有 CompositeLayer”这个项目约束，不应脱离语境复制。
