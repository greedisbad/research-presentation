# S 级主张证据审计（2026-09-08）

## 审计目的

本轮只审计长版母版中承担主线的 5 个 S 级切片。判断对象不是“文档写得是否完整”，而是演讲中的一句话能否由现有证据直接支持。

裁决口径：

- **FULL**：现有一手材料或当前可复现实验足以支持这句限定后的表述；
- **PARTIAL**：主链存在，但有历史、版本、样本或环境断点，必须降低措辞强度；
- **NONE**：目前不能上升为事实，只能作为假设、待办或明确标注的个人经验。

“可上台”不等于“证据无缺口”。只要主张被收窄到证据实际支持的范围，并在页内或讲者备注保留边界，PARTIAL 也可进入主体。

## 总裁决

| ID | 主张角色 | 审计结论 | 上台状态 | 冻结前动作 |
|---|---|:---:|:---:|---|
| T01 | 信息缺口到来源的路由规则 | FULL（本地案例） | READY | 不得扩写成“普遍提高效率” |
| D01 | 把模糊失败改写为可证伪问题 | PARTIAL | READY | 明示为事后复盘，不伪造最初失败现场 |
| D02 | 文档、源码、相邻实现和运行实验分工 | PARTIAL/较强 | READY-CHECK | 复核 Deck.gl 9.1.12 官方入口和版本源码 |
| W04 | 外部参考经筛选后进入协议、adapter 和门禁 | FULL（下载快照）；真机效果 NONE | CONDITIONAL | 补 WPS 真机结果；否则页尾保留“真机未验收” |
| V02 | 视频无字幕时的可执行降级链 | FULL（单样本流程）；内容准确性 PARTIAL | READY | 不引用未经回听的 ASR，不外推到旧 123 份 |

## T01：信息缺口 → 来源路由

### 可安全使用的主张

> 在 Tabloom 这个项目中，平台能力、产品价值、代码行为、模型返回和发布状态被拆成不同信息缺口，并分别由官方文档、原型反馈、源码/测试、真实 API 输出和 Git/远端回答。

裁决：**FULL（限定为本地案例）**。

### 证据链

`设计/实施/复盘材料 → 源码与测试 → Git 时间线 → 2026-09-07 Node 24 重跑报告`

当前运行快照包含 37 项测试和扩展结构验证；它证明材料所描述的代码状态在记录环境中可运行，不证明所有历史搜索步骤均完整保存。

### 不支持的扩展表述

- “这种来源路由普遍提高调研效率”：**NONE**，无对照组、耗时或质量测量；
- “AI 自动完成了全部调研判断”：**NONE**，材料中包含用户反馈、取舍和验收；
- “完整记录了当时所有搜索”：**NONE**，查询与工具日志不全。

### 视觉与讲法

视觉可直接重画为六行路由表。不要把 37 项测试画成方法有效性的量化证明；它只是当前案例状态证据。

## D01：失败现象 → 可证伪问题

### 可安全使用的主张

> Deck.gl 复盘把“页面能开但旋转不对”拆成对象边界、数据语义、生命周期、版本兼容和非功能约束五类可查问题；这让后续检索可以分别指向 API、源码和运行实验。

裁决：**PARTIAL**。拆题结构、当前基线和复盘文档存在，但原始聊天、最早生成物和完整时间线缺失。

### 证据链

`IMPLEMENTATION-NOTES.md 固定行号与哈希 → 当前错误/正确单位对照页 → 当前浏览器采集结果`

这条链足以证明“本案例如何复盘和重写问题”，不足以证明当前基线就是当时最早的失败文件，也不足以比较不同模型的能力。

### 不支持的扩展表述

- “这是原始失败现场”：**NONE**；
- “五类拆题能覆盖所有前端问题”：**NONE**；
- “继续改 Prompt 一定不如读源码”：**NONE**。

### 视觉与讲法

可展示当前 radians 对照截图，但标题应写“为复盘保留的可运行对照”，不能写“AI 第一次生成的失败页面”。

## D02：文档 → 同版本源码 → 相邻范式 → 实验

### 可安全使用的主张

> 在 Deck.gl 9.1.12 案例中，公开契约由官方文档回答，版本实现由同版本源码回答，扩展接线参考同仓库相邻实现，最终行为由真实浏览器裁决；运行失败还会触发下一轮更窄的检索。

裁决：**PARTIAL/较强**。复盘记录、当前实现、采集脚本和 2026-09-05 浏览器报告形成了主链；但当时网页快照、首次 shader linking error 日志和上游源码快照未冻结。

### 证据链

`官方入口记录 → 9.1.12 源码片段记录 → 相邻 extension 迁移说明 → 四路由浏览器报告与截图`

运行报告可支持当次 HTTP、帧推进、像素变化、picking、暂停等门禁，不是跨 GPU、跨浏览器性能基准。

### 不支持的扩展表述

- “源码永远比官方文档可靠”：**NONE**，两者回答的问题不同；
- “当前截图证明动画持续运行”：**NONE**，静态截图只能辅助展示，动态事实来自采集指标；
- “接近 60 FPS”：除非在冻结前保留明确测试环境和采样值，否则不作比较性或性能承诺。

### 视觉与讲法

证据阶梯与运行报告字段可以进入主体；具体 accessor、shader uniform 和角度换算只留附录。

## W04：参考项目 → 可迁移资产 → 运行门禁

### 可安全使用的主张

> 在当前 WPS 插件下载快照中，外部 PPT 项目先按浏览器 JavaScript 宿主、原生可编辑输出和迁移成本筛选，再把 Design Token 与 Content Schema 转成共享 Theme、SlideSpec、语义工具和两类 adapter；相关 mock 测试与生产构建已通过。

裁决：前半句与自动门禁为 **FULL（限定到当前下载快照和当次环境）**；“真实 WPS 中正确生成且视觉良好”为 **NONE**。

### 证据链

`候选与可行方案文档 → themes/SlideSpec/tools/adapter 源码 → theme smoke → 49 项窄测 → 58 项全测 → Vite 构建`

下载包没有独立 Git 历史，因此这条链证明“当前材料与实现存在对应”，不能精确归因到某次历史提交或某个外部仓库。

### 不支持的扩展表述

- “11 个候选中找到了一个可直接复用的最佳项目”：**NONE**，实际是拆取局部资产；
- “Browser adapter 通过，所以 WPS 可用”：**NONE**；
- “生成结果视觉质量优秀”：**NONE**，需要 WPS 真机和人工视觉验收。

### 视觉与讲法

若冻结前补到真机素材，可用“候选—协议—adapter—自动门禁—宿主结果”完整链。若未补到，主体仍可讲迁移方法，但必须在同页显式保留“真机未验收”，不能仅藏在讲者备注。

## V02：网页失败 → API → 音频 → ASR → 外证

### 可安全使用的主张

> 对 `BV1DVwLz2EGv` 这个单样本，视频页返回 412 且无公共字幕后，流程仍通过平台 API、DASH 音频和三段本地 ASR 恢复了可搜索候选文本；专名和数字错误再由作者文章回链或降级处理。

裁决：流程可执行为 **FULL（单样本）**；“视频内容已准确转写”为 **NONE**；“主工作流结构与作者文章对应”为 **PARTIAL/较强**。

### 证据链

`平台响应哈希 → 音频格式/时长/哈希 → 三个固定 90 秒窗口 → 带时间戳 ASR 摘要 → 同作者文章对应关系`

原始平台 JSON、音频和 ASR JSON 留在本地忽略目录；公开仓库保留 manifest、指纹、脚本和抽样审计。两段有较强文章对应，一段覆盖不足；全程未完成人耳回听。

### 不支持的扩展表述

- “整段 1367 秒已准确转写”：**NONE**，只抽样 270 秒；
- “作者文章是独立交叉验证”：**NONE**，它是同作者的一手文字回链；
- “此前 123 个文件全部成功且准确”：**NONE**，旧原始对象未恢复；
- 未回听 ASR 的逐字引语、产品名和数字不得进入核心页。

### 视觉与讲法

最强画面不是视频观点本身，而是降级链和 `2025 → 2005` 错误。它能说明“转写先把不可搜索媒介变成候选语料，可靠证据仍需回链与人工校正”。

## 对长版母版的直接约束

1. 五个 S 级切片均可继续承担主线，但 W04 在真机补证前保持 **CONDITIONAL**。
2. 所有案例句首优先使用“在这个项目/这个样本中”，避免从单案例外推普遍效率。
3. 数字只能证明记录范围或当次门禁，不自动证明方法质量：37/49/58 项测试、270/1367 秒与旧 123 份尤其如此。
4. “官方文档—源码—实验”不是权威性排行榜，而是问题—证据匹配关系。
5. 截图负责让观众看见对象，机器报告负责证明动态事实；两者不能互相替代。

## 审计结论

本轮没有把任何 S 级切片降级删除，但收紧了五类易被夸大的表述：效率因果、原始历史、跨环境性能、WPS 真机效果和视频转写准确性。后续制作演示时，应优先复制本文件中的“可安全使用的主张”，再从各切片回读原始位置与视觉素材。
