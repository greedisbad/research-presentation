# 证据切片优先级与重复观点审计

## 审计目标

本文件解决两个不同问题：

1. 某个切片的证据是否值得保留；
2. 某个切片是否应在演讲主体中独立占据一页或一段。

两者不能混为一谈。一份材料可以很有证据价值，但与另一份切片表达同一个方法观点，因此不必在主体重复讲述。

本轮不删除研究底稿。“合并”只表示在长版故事板中由一个主切片承担观点，其他切片作为补充证据、备援案例、讲者备注或附录。

## 优先级定义

| 级别 | 在长版母版中的处理 | 进入 45 分钟版的默认倾向 |
|---|---|---|
| S | 承担主线不可替代的决策、流程或核心案例转折 | 优先保留，即使压缩也要保留 takeaway |
| A | 有独立价值，能加强迁移性、完整性或可操作性 | 按转场和时间选用，可压成短例子 |
| B | 证据值得保留，但与主线重复、偏验证细节或需要较多前置上下文 | 优先讲者备注或附录 |
| D | 不进入演示叙事，仅作为底层取证、问答或反证材料 | 不制作独立页 |

级别不表示事实真伪，也不表示文档质量；它只表示对当前演讲主线的边际贡献。

## 统一裁决

| ID | 最终级别 | 独立职责 | 为什么不再更高/更低 | 故事板动作 |
|---|:---:|---|---|---|
| T01 | S | 定义“信息缺口 → 证据源路由”的总方法 | 它是全场搜索与阅读行为的导航规则；但不独立承担工程证明 | 方法论主页；后续案例反复回指 |
| D01 | S | 展示失败现象如何重写为可证伪问题 | 与 T01 相关，但负责从抽象规则落到真实故事的第一个转折 | Deck.gl 案例开场 |
| D02 | S | 展示文档、同版本源码、相邻范式与运行实验的分工 | 是“怎么看、怎么找、怎么升级证据”的最完整工程转折 | Deck.gl 核心页组 |
| W04 | S | 证明外部参考经宿主筛选后，进入数据协议、工具、adapter 和分层门禁 | 直接连接“搜索参考”和“可用开发资源”；真机证据仍缺失 | WPS 主页组的骨架 |
| V02 | S | 展示网页 412、无字幕、音频、本地 ASR、识别错误和作者文章回链的降级链 | 它是当前视频案例中可重跑且证据边界最清晰的单样本 | 视频案例主页组 |
| W01 | A | 展示如何建候选池，并把参考拆成代码、参数、模式和原则 | 与 W04 的前半段重合，但候选分类的教学价值不应丢失 | 合入 W04 前置；详细四分类可独立长版页 |
| W02 | A | 展示调研结论如何从 Prompt 下沉为 schema 和 executor 能力 | 独立回答“一次知识如何变成轻 Agent 可复用能力”；但只有局部运行记录 | WPS 结尾或“沉淀为工具”转场 |
| V01 | A | 展示多查询、候选筛选与按问题重组的批处理层 | 与 V02 共享下载/ASR/外证流程，且旧 123 份原始转写缺失；但它独立承担“从单视频到问题视图” | 作为 V02 的规模化前后景，不重复讲降级链 |
| DI01 | A | 用 Confirmed / Rejected / Unverified 与 task brief 保存跨会话状态 | 是唯一专门承担“调研记忆如何给下一个 Agent 消费”的切片；不宜扩展游戏业务 | 1 个短案例或结尾模板 |
| X01 | A | 在非用户原始案例上重跑“地图—迭代检索—最小实验” | 内容小但能抵消“只是事后包装”的质疑；不必讲 p-limit 细节 | Deck.gl 后 60 秒迁移证明，时间紧可附录 |
| D03 | B | 保留三条生产路线和一条诊断基线的完整比较 | 证据强，但容易把注意力带到 Deck.gl 实现选型，偏离调研主题 | 长版/附录决策矩阵；主体只保留“共享门禁下可比” |
| W03 | B | 保留相邻 API 失败、放弃路线和规则沉淀的 WPS 证据 | 与 DI01 的负知识主张重叠，而 W04 已经承担 WPS 的主叙事 | 作为 DI01 的跨案例支持或问答备用 |
| T02 | B | 区分传输、结构、业务和人工有用四层验收 | 案例鲜明，但验证不是本次演讲主体，且原始脱敏 JSON 未单独归档 | 验证段的短反例或附录 |
| A01 | B | 演示一条引用如何因为证据不足而降级表述 | 方法可操作，但引用审计只应作为收尾质量门，且仍需冻结日官方页快照 | 附录或现场简短修句示例 |
| P01 | B | 比较三个案例的证据完整度与断点 | 是审计工具，不是新案例；主体重复展开会使验证抢走搜索与转化的主线 | 附录总表或讲者备注 |

## 重复观点簇与主证据归属

### 簇 1：信息缺口驱动检索

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 方法定义 | T01 | 给出信息缺口到来源的通用路由表 |
| 核心故事 | D01 | 展示一个模糊失败怎样被改写为五类问题 |
| 迁移反证 | X01 | 在陌生小仓库中记录查询词汇如何逐轮收窄 |

处理：三者不合并文件。长版先讲 T01，用 D01 落地，X01 仅证明方法能在新对象上重跑。45 分钟版时可删 X01，不删其证据底稿。

### 簇 2：从参考到可执行资源

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 候选发现与分类 | W01 | 展示“不是整仓照搬”如何具体执行 |
| 完整转化主链 | W04 | 从宿主筛选一直追到 Theme/SlideSpec、adapter 和门禁 |
| 知识下沉细节 | W02 | 用一个局部前后对照说明 Prompt 怎样变成工具能力 |

处理：W04 承担主叙事，其开头吸收 W01 的筛选结果；W01 的四分类留在长版独立页或备注。W02 保留，因为它回答的是“如何让轻 Agent 复用结论”。

### 簇 3：视频从发现到可引用资料

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 规模化与问题重组 | V01 | 支持查询矩阵、元数据筛选和按研究问题建视图 |
| 单样本恢复与降级 | V02 | 有当前可复核的平台、音频、ASR 指纹和作者文章回链 |

处理：视频案例以 V02 的真实单链为主，V01 只补“为什么需要批量筛选与按问题聚合”。不在两处重复讲下载和 ASR。

### 簇 4：负知识与跨会话交接

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 主方法 | DI01 | 三栏状态、状态迁移和 task brief 最完整 |
| 跨案例支持 | W03 | 说明负知识可以从运行反证进入 Learnings 和项目规则 |

处理：主体只用 DI01 讲完整方法。W03 作为“这不只在游戏项目发生”的一句跨案例互证，不再展开第二套负知识流程。

### 簇 5：证据升级、迁移实验与谱系审计

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 主案例 | D02 | 证据层次与运行失败触发新检索的故事完整 |
| 迁移实验 | X01 | 展示相同方法在新仓库上的可执行性 |
| 审计工具 | P01 | 不证明方法有效，只用来暴露三个案例的证据断点 |

处理：主体只用 D02 讲证据升级。X01 是“可迁移”的短证明，P01 放附录。三者的数据不合并，但不在主体重复讲三次“文档—源码—实验”。

### 簇 6：验证与引用质量

| 角色 | 切片 | 保留理由 |
|---|---|---|
| 候选路线可比 | D03 | 共享门禁使方案比较不只靠偏好 |
| AI 业务结果门禁 | T02 | 显示 schema 合法不等于业务有用 |
| 引用降级 | A01 | 显示来源存在不等于完整支持当前表述 |
| 证据断点比较 | P01 | 显示不同案例只能声称到不同强度 |

处理：这四份都保留在长版和附录候选池，但不构成第四个主案例。45 分钟版只保留“验证媒介匹配失败媒介”的总原则，再视时间选一个短反例。

## D 级内容：不制作独立主页

当前 15 个证据切片均有底稿或附录价值，因此不把整份切片降为 D。D 级用于切片内部的细节：

- Deck.gl 具体 accessor、角度换算位置与 shader uniform 语法；
- Dice 游戏规则、角色和完整测试数量；
- WPS 内部工具名、长代码与具体对象模型差异；
- 旧视频聚合中无法回到原始媒体的数字、逐字引语和准确率声明；
- Tabloom 具体 Chrome API、模型参数与完整提交列表；
- p-limit 的具体库行为，除非作为现场问答。

这些细节继续保留在证据文档中，但不单独生成演示页。

## 长版母版的最小观点所有权

| 主要观点 | 唯一主切片 | 辅助切片 |
|---|---|---|
| 从信息缺口出发 | T01 | D01、X01 |
| 把失败改写为可证伪问题 | D01 | T01 |
| 不同证据源回答不同问题 | D02 | T01、X01 |
| 将开源参考拆成可迁移资产 | W04 | W01 |
| 把自然语言经验沉淀为工具能力 | W02 | W04 |
| 把非文本媒介恢复为可搜索证据链 | V02 | V01 |
| 按研究问题而非按视频重组资料 | V01 | V02 |
| 让调研状态跨会话积累 | DI01 | W03 |
| 在共享验收下比较多条路线 | D03 | D02 |
| 区分结构合法与业务有用 | T02 | W04 |
| 使引用强度与来源支持匹配 | A01 | P01 |
| 暴露证据链断点 | P01 | V01、W04、D02 |

此表是后续故事板去重的直接输入。若一张新页无法说明它拥有哪个新观点，就应合并到表中的主切片，而不是继续增加一页相似流程图。

## 审计结论

- S 级 5 个：T01、D01、D02、W04、V02。
- A 级 5 个：W01、W02、V01、DI01、X01。
- B 级 5 个：D03、W03、T02、A01、P01。
- D 级 0 个完整切片；D 级仅标记不应制作独立页的案例内部技术细节。

本轮的去重结果不是“删掉 5 份 B 级文档”，而是把 15 份材料的表达权收敛为 12 个不重复的主要观点，并为每个观点指定唯一主切片。
