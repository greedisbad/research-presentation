# P01：三条主张的证据谱系审计

## 审计目标

验证本项目提出的“六节点证据谱系”能否用于真实材料，而不只是一张概念图。这里选择三个性质不同的主张：可重复运行的 Deck.gl 案例、有实现映射但缺历史的 WPS 案例、聚合产物存在但原始转写缺失的视频案例。

审计日期：2026-09-05。哈希用于识别本次读取的文件版本，不表示这些文件都已收录在公开仓库。

## 谱系一：Deck.gl——失败应升级为文档、源码与实验问题

### 最终可用表述

> 在这个 Deck.gl 案例中，把模糊的“旋转不工作”拆成 API、单位、生命周期和性能问题，再分别查公开契约、目标版本源码和同仓库范式，最终形成了四个可运行实验。

| 节点 | 可追溯内容 |
|---|---|
| 决策问题 | 怎样实现持续旋转，同时保持 picking、静态层不重复初始化并接近 60 FPS |
| 查询/定位动作 | 按 accessor、角度单位、Layer lifecycle、shader module 四个槽位查询 |
| 原始来源 | Deck.gl 官方文档、9.1.12 源码、同版本 BrushingExtension；索引见 `IMPLEMENTATION-NOTES.md` 29–104 行附近 |
| 证据片段 | `getAngle` 契约、shader 内部角度转换、同仓库 uniform module 写法 |
| 转换规则 | 每个假设形成独立路线；错误单位另建 baseline，不用一次实现同时证明全部主张 |
| 验证结果 | 结构测试 9/9；2026-09-05 Chromium 四页门禁 4/4，详见 `runtime-report.json` |

## 横向结论

| 案例 | 来源可定位 | 转换可解释 | 当前可重跑 | 关键断点 | 上台用途 |
|---|:---:|:---:|:---:|---|---|
| Deck.gl | 是 | 是 | 是 | 初版失败历史 | 完整正例 |
| WPS | 是 | 是 | 部分 | Git 历史、WPS 真机 | “迁移而非复制”正例 |
| 视频 | 部分 | 是 | 脚本可读、数据不可重跑 | 音频、ASR、日志 | 断链反例 |

最适合演讲的不是把三条都包装成成功，而是让它们承担不同角色：Deck.gl 证明完整闭环长什么样，WPS 证明设计来源怎样落进代码，视频证明中间件缺失后哪些话必须降级。

## 可复核性测试结果

本轮从证据切片出发，逐一回到列出的本地路径、行号和运行快照：

- 三条主张都能找到当前所引用的聚合或实现文件；
- Deck.gl 当前成功结果可以重跑；
- WPS 的“来源到实现”能定位，但精确历史因果不能恢复；
- 视频的原始媒体链确实无法从当前目录恢复。

因此六节点模板能够暴露断点，但尚未经过第二位独立读者测试。“别人一定能复现”仍是待验证项。
