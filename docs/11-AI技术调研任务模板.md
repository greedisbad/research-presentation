# AI 技术调研任务模板

这不是“万能提示词”清单，而是一组不同流水线节点的任务合同。每个模板都要求 AI 交付证据、边界与下一步，而不是只生成流畅答案。

## 1. Research Brief：把主题改写成决策

```text
我要为【项目/场景】决定【具体决策】。

已知环境：【语言、框架、宿主、版本、团队约束】
必须满足：【成功标准】
不可接受：【风险/成本/许可证/隐私边界】
候选范围：【已知方案，可为空】
截止日期与预算：【时间/费用】

请先不要给方案。先输出：
1. 需要回答的原子问题；
2. 每个问题最合适的一手来源类型；
3. 纳入/排除标准；
4. 哪些问题只能通过实验回答；
5. 停止条件和最终决策表字段。
```

## 2. 查询矩阵：扩展检索空间

```text
围绕【研究问题】，生成查询矩阵，不直接下结论。

按这些轴扩展：
- 概念同义词、旧名称、缩写；
- 错误消息、API symbol、配置键；
- 官方文档、源码、Issue/PR、Release、标准/论文；
- 支持证据与反对证据；
- 当前版本与历史版本；
- 中文与英文术语。

每个查询说明：它要填哪个证据缺口、优先在哪类站点搜索、命中后如何验真。
避免只换几个近义词的重复查询。
```

## 3. 来源初筛：先建候选池

```text
审阅以下搜索结果，只做初筛，不综合答案。

对每项返回：
- canonical URL、作者/机构、发布日期、访问日期；
- 来源类型：官方/标准/论文/源码/维护者/二手/聚合；
- 回答的原子问题；
- 是否值得阅读全文；
- 重复来源或转载关系；
- 淘汰理由；
- 时效和利益相关风险。

不要根据摘要补写网页中没有的内容。无法打开时标为“未核验”。
```

## 4. 来源卡：事实、推断、行动分开

```text
阅读【URL/文件】并生成来源卡：

1. 可直接由原文支持的原子事实；
2. 每条事实的精确定位（章节/页码/代码版本）；
3. 我们据此做出的推断，单独列出；
4. 可执行信息：API、代码模式、配置、约束、测试方法；
5. 来源自身未回答的问题；
6. 与已有来源的冲突；
7. 适合进入演示的程度 S/A/B/C/D 及理由。

不使用大段原文，不把推断写成原文结论。
```

## 5. 源码考古：从 symbol 追到发布

```text
在【仓库与目标 commit/tag】研究【能力/错误】。

请定位：
- 入口、核心 symbol、调用方、异常分支；
- 对应测试及它没有覆盖的条件；
- 引入关键行的 blame/commit；
- 相关 Issue、linked PR 与被拒绝方案；
- 修复首次出现在哪个 release/tag；
- 许可证与第三方依赖。

用表格返回“证据 → 原子事实 → 工程影响 → 未验证点”。
若 main 已修复但 release 未包含，必须明确区分。
```

## 6. 反证代理：专门攻击当前结论

```text
当前暂定结论是：【结论】。
当前证据是：【来源清单】。

你的任务不是润色，而是尝试推翻或收窄它：
1. 找官方弃用说明、breaking changes、失败 Issue、负面实证研究；
2. 检查来源是否同源转载；
3. 找与目标环境不一致的版本、人群、任务与规模；
4. 列出最可能让结论失效的三个条件；
5. 说明需要什么实验才能消除关键不确定性。

只收录能够改变决策或边界的反证。
```

## 7. Claim Auditor：逐句核验成稿

```text
把以下草稿拆成最小可验证主张。逐条标记：
- supported：来源直接支持；
- partial：来源只支持一部分或范围更窄；
- inference：合理推断但不是来源原话；
- unsupported：没有证据；
- stale：版本/日期可能过期；
- conflict：来源相互冲突。

对每条给出最佳来源和精确定位。引用存在但不支持该句时，也算失败。
不要用模型常识填补证据空白。
```

## 8. 从研究到实验

```text
基于已核验材料，为【关键不确定性】设计最小 spike。

要求：
- 一个明确假设；
- 与生产环境最接近的最小条件；
- 可观察的成功/失败标准；
- 固定版本与测试数据；
- 不接触真实秘密或客户数据；
- 失败后能安全清理；
- 输出命令、日志和产物位置；
- 区分 mock 通过与真实宿主通过。

先给实验方案，未获授权不要扩大写入或部署范围。
```

## 9. 停止检查

```text
根据本轮候选池、来源卡和 claim ledger 判断是否继续搜索。

返回：
- 尚无一手证据的高风险问题；
- 本轮新增的方案/约束/反例；
- 哪些新来源只是重复；
- 加入反证后候选排序是否改变；
- 下一小时搜索、实验、访谈、写作中哪项边际价值最高；
- 继续/停止的可审计理由。
```

## 10. 使用原则

- 模板里的环境、版本和成功标准比修辞更重要。
- 将广度搜索、来源提取、反证、引用审计分开，便于发现每一阶段的失败。
- 在输出 schema 中保留 `unknown`、`not found`、`conflict`，避免强迫模型填满表格。
- 对高风险动作，提示词不是权限控制；仍需要工具层限制与人工确认。
