# 研究工作台与日常节奏

这份文档把方法论落到一天的实际工作。目标不是每次都运行完整流程，而是让轻量任务也保留最小证据，让高风险任务自然升级。

## 1. 三档研究模式

| 模式 | 适用任务 | 时间盒 | 最小产物 |
|---|---|---:|---|
| 快速侦察 | 理解术语、寻找方向、会前准备 | 15–30 分钟 | Brief、3–5 个候选、一手种子、未知项 |
| 决策研究 | 技术选型、陌生 API、依赖选择 | 2–8 小时 | 查询矩阵、来源卡、候选表、反证、spike、决策记录 |
| 高风险审查 | 架构、安全、合规、不可逆迁移 | 多日 | 多人复核、威胁模型、完整实验、责任人批准、监控计划 |

升级条件：出现许可证不清、生产数据、权限扩大、不可逆迁移、相互冲突的一手来源，或失败成本超过预设阈值。

## 2. 推荐目录结构

```text
research/
├── brief.md                 # 决策、范围、环境、停止条件
├── queries.md               # 查过什么、为何查、哪些无效
├── candidates.csv           # 候选池与筛选字段
├── sources/
│   ├── bookmarks.md         # 全量书签
│   └── cards/               # 重要来源卡
├── claims.md                # 原子主张—来源—边界
├── experiments/             # spike、环境、日志、结果
├── decision.md              # 选择、反对意见、剩余风险
└── learnings.md             # 可写回 Skill/AGENTS/测试的知识
```

小任务可以合并文件，但不能删除“决策、证据、未知、验证”四个概念。

## 3. 一天的节奏

### 上午：建立地图

1. 用 10 分钟写 Research Brief。
2. 用 AI 生成问题槽位和查询矩阵，人删去跑题项。
3. 先找官方/源码种子，再做 snowballing。
4. 只收元数据建候选池，避免一开始被第一篇长文锁定方向。

### 中段：证据化

1. 按风险和信息增益选择全文。
2. 每读一个重要来源立即写来源卡。
3. 把结论拆成 claim ledger；没有定位的句子先不进正文。
4. 单独运行反证任务，检查弃用、失败 Issue、版本错配和利益相关。

### 下午：转入工程

1. 对无法靠阅读决定的问题做最小 spike。
2. 将运行结果、环境和失败日志纳入证据。
3. 做一次停止检查：继续搜、实验、请教专家还是开始写作。
4. 把稳定知识沉淀为测试、脚本、Skill、ADR 或仓库说明。

## 4. 每轮必须保留的失败信息

- 无效查询：为什么噪声大或发生 query drift。
- 无法访问的来源：反爬、登录、链接失效，不假装已核验。
- 被淘汰候选：版本、许可证、维护或集成成本不合格。
- 被推翻主张：原句、反证、修正后的范围。
- 实验失败：环境、错误、替代假设和是否值得重试。

失败日志的价值在于阻止未来的 Agent 和同事重复花费，而不是证明过程曲折。

## 5. 交接格式

研究中途停止时，用以下五句话即可让下一位继续：

```markdown
- 当前要支持的决策：
- 已有最强证据与位置：
- 当前候选排序及原因：
- 尚未解决的高风险问题：
- 下一步最有价值动作与停止条件：
```

## 6. 本项目今日样例

本轮研究遵循了同一节奏：从开源复用缺口出发，加入 GitHub Licensing、Code Search、Dependency Graph、OpenSSF 与 OSV；再沿实现证据链补 Issue/PR/Release；随后发现 Agent 读取外部内容还有提示注入风险；最后用停止条件和评测方法约束“无限研究”与“虚假提效”。

它说明查询矩阵不是一次性清单：新证据会暴露新的风险槽位，再触发有目的的下一轮搜索。
