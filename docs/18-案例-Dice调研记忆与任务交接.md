# 案例：Dice——让调研结论跨阶段积累

## 案例定位

Dice 项目的游戏代码不是本次演讲重点。三份会话复盘值得保留，是因为它们展示了 AI Agent 如何在多日、跨阶段任务中保存研究依据、失败路线和交接上下文。

原始材料：

- `<本地案例目录>/dice-game/docs/research/2026-08-31-session-retrospective.md`
- `<本地案例目录>/dice-game/docs/research/2026-09-01-session-retrospective.md`
- `<本地案例目录>/dice-game/docs/research/2026-09-02-session-retrospective.md`

## 一、它补充了“搜索之后怎么办”

常见 AI 调研流程停在“找到资料并总结”。Dice 复盘显示，资料只有进入以下链条，才会在长期工程中持续产生价值：

```text
研究问题
  → 来源与授权判断
  → 设计决策
  → 实施计划和任务 brief
  → 风险优先的纵向切片
  → 测试与真实环境观察
  → 会话复盘和后续交接
```

每一阶段都产生下一阶段能直接消费的文件，而不是依赖聊天记录或操作者记忆。

## 二、风险最高处先做一个纵向切片

角色资产阶段没有一次导入全部资源，而是先导入一个真实 GLB，验证加载、材质、骨骼、姿态、动画和构建链，再扩展为其他角色，同时保留程序化 fallback。

这一做法可以抽象为：

> 搜索结束的标志不是“资料读完了”，而是主方向、授权、技术边界、fallback 和验收标准已经足以支持一个最小纵向切片。

纵向切片的作用是尽早回答最昂贵的未知项。成功后再批量展开；失败时也只损失一个样例的投入。

## 三、把“不要重复研究”当作正式资产

复盘持续记录：

- 已比较并排除的资产或技术路线；
- 已确定的许可证与来源；
- 已验证的架构边界；
- 当前仍未验证的风险；
- 失败的环境与工具路径；
- 后续阶段不应重新争论的决定。

这是一种负知识库。它保存的不只是“最后选了什么”，还保存“为什么其他路线不必再走”。对于没有长期记忆的轻量 Agent，这类文件尤其重要。

建议在 `LEARNINGS.md` 中固定三个区块：

```markdown
## 已确认，可直接复用
## 已排除，不要重复尝试
## 尚未确认，下次优先验证
```

## 四、评审意见也是待核验信息

词汇惩罚阶段出现过一个很有教学价值的情形：评审者声称定时器测试缺失，但实际测试位于另一个文件。主线程没有因为“评审说了”就重复实现，而是检查 diff、目标文件和测试输出后驳回误报；同一轮评审中发现的旧定时器所有权问题则有证据支持，因此被接受并修复。

这与网页搜索的判断规则完全一致：

```text
Finding（别人或 AI 提出的判断）
  → 定位它声称涉及的文件或行为
  → 检查 diff、测试和运行结果
  → 必要时复现
  → 给出 Accept / Reject / Defer 裁决
```

适合演讲的抽象结论是：

> AI 评审不是答案层，而是新的候选证据层；它也需要来源定位和复核。

## 五、任务 brief 是搜索结果到执行任务的接口

复盘中较有效的协作方式不是把整段对话转发给执行者，而是给出边界明确的任务 brief：

- 任务目标和非目标；
- 所有权文件或模块；
- 已确定的接口；
- 必须阅读的证据；
- 验收命令；
- 交接时必须报告的风险。

这说明结构化调研文档不仅服务人类阅读，也可以成为下一位 Agent 的输入协议。

## 六、演讲抽象层

### 推荐进入正文或案例串联（A）

- 调研结论必须落入可版本化文件，才能跨会话积累；
- 从最高风险点做一个真实纵向切片，再决定是否扩大实现；
- 保存“不要重复研究/尝试”的负知识，可以显著减少后续上下文和搜索浪费；
- 任务 brief 是研究结果到执行 Agent 之间的接口；
- AI 评审也只是待核验信息，不能跳过证据裁决。

### 适合结尾或附录（B）

- 逻辑测试、集成边界、构建检查、真实浏览器观察四层验证；
- 主线程保留跨模块、产品语义、视觉判断和最终裁决；
- 环境缺失、连接失败、目录错误和评审漏读文件等失败记录。

### 不进入 PPT 主体（D）

- 游戏规则、角色职业、骰盅尺寸和词汇惩罚的业务细节；
- Zustand、R3F、定时器和组件文件的具体实现；
- 提交哈希和完整测试数量；
- 三份复盘的逐日时间线。

## 七、证据边界

- 这是连续项目复盘，不是对任务 brief、子 Agent 或 Codex 效率的对照实验。
- 复盘中的“有效”“节省”等判断主要是工程经验，应作为方法建议，不写成普遍因果结论。
- Dice 案例在正式演讲中只承担“调研记忆与交接”角色，不应抢占 WPS、视频和 Deck.gl 的案例篇幅。
