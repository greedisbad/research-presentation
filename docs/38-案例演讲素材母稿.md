## B747：从一张看不懂的货舱图进入专业资料

### 背景

需求来自一个 3D 配载相关项目。页面需要理解 B747-400F/SF 主货舱的位置、轮廓和可用空间，才能把 ULD 或货物放进近似正确的几何环境。起点不是一份整洁的参数表，而是一张带有位置编号、缩写、轮廓线和局部数字的业务图。

对航空公司听众而言，货舱位置和构型并不陌生；真正值得讲的是，一个并不掌握完整专业词汇的 Agent，如何从现有图中找到进入专业资料体系的入口。

### 可见问题

- 直接搜索“B747 货舱尺寸”会得到整机尺寸、新闻图片、模型玩具和大量重复网页；
- 图上的 `A1/A2/B1`、`LR/LL/PL`、`11P` 等符号缺少解释，无法立即判断是位置、方向、板箱还是构型；
- 相似机型、改装型、航空公司配置和不同手册中的数字可能冲突；
- 即使找到轮廓图，也未必能直接转成 3D 坐标和碰撞边界；
- 公开资料只适合建模预判，不能替代公司内部 W&B / Cargo Loading Manual 和正式装载批准。

### AI行动

1. 先从图中提取低频符号，而不是把整段需求改写成更长的自然语言 Prompt；
2. 将机型、货舱、位置、轮廓与两个罕见代码组合查询，观察哪些术语共同出现；
3. 从 `PA1/PA2/PMD/H4M/HPL/PEB` 一类 contour code 继续追到专业图表和手册语境；
4. 当文字描述不足时，将多个尺寸数字组合成“数字指纹”，反查同一张或同源图表；
5. 给来源分工：航空公司材料确认业务构型和应用语境，制造商/手册确认几何与定义，二手文章和搜索摘要只提供线索；
6. 遇到 SF、ERF、航空公司改装和不同舱位布局时，保留冲突和配置标签，不做无依据平均；
7. 把找到的事实转换成“轮廓折点、适用位置、来源、置信度、待确认项”，供建模和业务人员继续确认。

### 关键转折

第一次转折是认识到：图上的罕见符号不是噪声，而是比“747 cargo”更好的搜索入口。

第二次转折是使用数字指纹。很多专业 PDF 的标题和网页描述并不包含业务人员熟悉的说法，但图内的一组尺寸很难在无关页面中同时出现。搜索从“找一篇介绍文章”变成“寻找拥有相同数据指纹的原始材料”。

第三次转折是停止追求唯一答案。同样叫 B747-400F 的资料可能对应不同构型；把冲突保存下来，比让 AI 选择一个看起来最完整的数字更安全。

### 工程产物

- 一条可复查的查询演化链；
- 位置、轮廓代码和来源之间的映射；
- 可进入 3D 项目的几何约束草案；
- 每项约束的置信度和未知项；
- 明确需要内部手册或业务专家确认的边界。

### 可讲细节

- 低频共现搜索：两个少见代码同时出现，比一个通用名词更能缩小资料空间；
- 数字指纹：不记网页标题，也可以用图中的一串尺寸重新找到材料；
- 来源并非“越官方越万能”：制造商资料能解释轮廓，航空公司内部资料才决定具体运营构型；
- AI 很适合先把 29 个位置、多个代码和冲突整理成表，人只需处理高风险分叉；
- 搜索产物不是“我找到一张图”，而是“这条几何约束为什么可以暂时使用”。

### 不能声称

- 不能说公开网页已经证明顺丰所有 B747 的实际装载限制；
- 不能把某一构型的左右轮廓和高度自动推广到全部飞机；
- 不能把搜索摘要、二手图表或 AI 识图结果作为正式装载依据；
- 不能暗示这次文档调研已经获得公司内部 W&B 或 Cargo Loading Manual；
- 不能把预判几何模型说成适航、机务或现场操作结论。

### 图片候选

1. **[待补证] 原始业务舱位图**：圈出罕见代码。能证明搜索入口来自真实材料；正式展示前需确认来源和内部信息边界。
2. **[示意图] 查询演化**：`747 cargo → 11P + H4M → contour code → 数字指纹`。能解释方法，不能冒充原始搜索截图。
3. **[网站图片] 专业 contour 图或 PDF 页**：能展示代码与轮廓关系；需重新核对链接、访问日期和展示权利。
4. **[示意图] 几何约束卡**：轮廓折点、适用构型、置信度、未知项。能展示资料如何进入开发，不证明数据已获业务批准。

## WPS：找巨人的肩膀，不等于找到一个巨人

### 背景

项目目标是在 WPS 的 Word、Excel、PPT 中提供 AI Agent，并通过 WPSJS 操作文档对象。它不是输出一张不可编辑的幻灯片图片，而是要在特定宿主、特定对象模型和可编辑交付要求下真正工作。

早期资料分散：官方文档能解释加载项和公开能力，却不足以直接给出整套 Agent 架构；GitHub 项目各有长处，但技术栈、输出格式和宿主不同。项目因此调查多个 PPT、文档和 Agent 相关仓库，没有选择一个“冠军项目”整体照搬。

### 可见问题

- 很多参考项目能生成漂亮 PPT，却依赖 Python、浏览器 HTML/CSS 或自有运行时；
- 同样是 Office 文档，VBA、Microsoft Office 与 WPSJS 的对象行为不能默认相同；
- Prompt 可以要求模型批量操作，但模型仍可能逐段、逐对象调用；
- 浏览器 mock 与单元测试能验证工具协议，却不能证明 WPS 真机对象模型和视觉结果；
- 某些最初看起来合理的功能路线，在实际宿主中不可靠，必须允许放弃。

### AI行动

1. 建立 11 个相关项目的候选池，先记录生成管线、布局、主题、编辑模型、质量门禁、宿主兼容和迁移难度；
2. 用当前宿主和交付约束筛选，而不是按 Star 或成品美观度排名；
3. 将参考拆成四类资产：代码/API 用法、设计参数、架构模式、验证方法；
4. 从不同项目分别取得 Content Schema、多步 Agent Loop、Design Tokens、布局坐标、字符预算和 QA 思路；
5. 把这些资产翻译成当前项目的 Theme、SlideSpec、工具 schema、adapter 和测试；
6. 使用 Browser Adapter 在普通环境验证协议和状态，使用 WPS Adapter 连接真实宿主；
7. 当 Prompt 约束反复失效时，把规则下沉到数组参数、规范化函数和执行器；
8. 将失败路线写入 Learnings 和项目规则，避免下一位 Agent 再走相同弯路。

### 关键转折

第一处转折是从“找最好的 PPT 项目”改成“找当前项目缺少的局部资产”。PPTAgent 可以贡献内容协议，HTML/PPT 经验可以贡献设计 token，另一个项目可以贡献布局和 QA，但它们都不必成为运行时依赖。

第二处转折是批量格式化。提示词已经说“请批量处理”，模型依然逐段调用。最终不是继续强化措辞，而是让工具接口直接接受索引数组。规则从语言建议变成结构能力。

第三处转折是承认失败路线。PPT 图表注入、相邻对象模型经验和某些段落写法，在宿主里没有按预期工作。项目没有把早期计划包装成成功，而是保留“放弃”和修正原因。

### 工程产物

- Theme：共享设计 token 和风格输入；
- SlideSpec / Content Schema：模型表达内容语义，稳定工具负责坐标与渲染；
- Agent Loop 与 Tool Adapter：将模型调用连接到当前宿主；
- Browser/WPS 双 adapter：分别处理协议验证和宿主验证；
- 工具测试、运行报告、Learnings 与 `AGENTS.md`；
- 2026 年 5 月的历史 WPS 真机画面。

### 可讲细节

建议重点展示一张“这里借一点、那里借一点”的图，而不是滚动 11 个项目名称：

```text
项目 A：内容协议 ──────┐
项目 B：设计参数 ──────┤
项目 C：Agent 编排 ────┼→ WPSJS Adapter + Tool Schema + Tests
项目 D：验证方法 ──────┤
官方文档：宿主边界 ────┘
```

来源分工可以用一个口播而非大表格：维护文档说明作者希望你怎样用，源码说明它实际上怎样做，Issue 暴露真实边界，提交历史解释变化原因，当前宿主运行决定这次能不能用。

WPS 案例也是“参考如何变成代码”的最佳证明：外部项目不是书签，而是在仓库中找到对应 Theme、adapter、tool schema 和测试位置。

### 不能声称

- 不能把历史截图说成当前版本已经通过完整真机门禁；
- 不能仅凭浏览器 mock 推断 WPS 客户端兼容和视觉正确；
- 不能宣称所有代码都由 AI 独立完成，除非另有明确提交口径；
- 不能说 WPS API 完全没有文档，只能说目标版本下存在资料和类型不完整的问题；
- 不能把一个 S 级来源整体等同于 S 级实施方案。

### 图片候选

1. **[项目图片] WPS 历史真机截图**：证明当时在 WPS 客户端中出现多页生成结果；不能替代当前版本验收。

5. **[项目图片] “已放弃”计划裁切**：证明调研允许否定原计划。

## Web Excel：人给标准，AI 替我们扩大选择

### 背景

原始需求是为 Vue 3 项目寻找“像 Excel 的复杂表格”。这句话看似具体，实际混合了两类产品：以整行记录为中心的业务表格，以及以单元格、选区和工作簿为中心的电子表格。

项目最终调查 14 个候选，筛到六个独立 HTML 实验，用同一批数据和相近操作比较免费边界、交互语义、CDN 形态与浏览器运行结果。

### 可见问题

- “免费”可能只指仓库某部分开源，不代表目标能力免费；
- “支持合并”可能指固定区域、行跨度或用户自由选区，语义不同；
- “支持 Vue”可能是原生组件，也可能只是能嵌入；
- CDN 返回成功状态不代表拿到浏览器可执行的完整包；
- 点击不报错不代表排序、移动或合并后的实例状态正确；
- 单机单次初始化数字不能构成性能排行榜。

### AI行动

1. 将需求拆成许可、Vue 3、排序筛选、列设置、行列移动、合并、性能、无需构建 HTML 和国内 CDN 等槽位；
2. 先区分业务记录表格与电子表格，避免跨产品类型做单一总排名；
3. 从官方仓库、官方文档、包元数据和许可证建立 14 个候选；
4. 按维护状态、免费功能边界和任务语义排除候选；
5. 对固定版本 CDN 依次验证元数据、文件存在、产物格式和真实浏览器加载；
6. 为六个候选生成同数据、同场景的独立 HTML；
7. 使用实例状态、部分真实鼠标操作和截图分别验证功能与外观；
8. 当用户追加 Univer 体积问题时，单独测量依赖组合，而不是重做全部排名；
9. 输出绑定当前需求的条件性建议。

### 关键转折

第一处转折是“像 Excel”被拆成产品类型。没有这个分叉，候选越多，排行榜越误导。

第二处转折是某个 `min.js` 返回成功，但内容只是一个 CommonJS 函数，而非需要的完整浏览器包。搜索与 HTTP 检查只能说明“拿到了东西”，不能说明“拿到了能用的东西”。

第三处转折是 Tabulator 行移动调用没有报错，但最终顺序不符合最初假设。闭环不是按钮提示“成功”，而是查询目标记录最后在哪一行。

### 工程产物

- 需求槽位和候选研究表；
- 固定版本 CDN 检查结果；
- 六个同数据、同操作的独立 HTML；
- 浏览器状态与交互结果 JSON；
- 桌面和移动截图；
- 条件性选型建议和未验证清单。

### 可讲细节

- AI 可以处理 14 个候选的重复调查，人集中决定哪些差异真正影响产品；
- 官方宣传页、仓库许可证、具体 npm 包和付费能力表不能混成一个“开源”标签；
- 同数据实验比功能列表更有说服力，因为它迫使候选回答同一个任务；
- 自动断言与截图互补：截图看到遮挡，实例状态证明行为；
- 用户追加问题不一定触发全局重做，可以进入一个更窄的专项调查。

### 不能声称

- 不能把当次建议说成所有 Vue 项目的通用排名；
- 不能把单次本机初始化时间说成性能基准；
- 不能由 CDN 在一台机器可达推出全国网络可达；
- 不能由截图推出拖动、筛选和合并正确；
- 不能把仓库开源自动等同于目标功能可免费商用。

### 图片候选

1. **[项目图片] 选型实验室索引页裁切**：展示 14 候选到六个实验，不能整张长图直接缩小。
2. **[项目图片] Jspreadsheet 与 VXE 截图**：展示两类产品的视觉差异；功能结论需配状态记录。
3. **[示意图] “像 Excel”分叉**：记录表格 / 电子表格，两边列出不同任务语义。
4. **[示意图] 四道 CDN 门**：元数据 → 文件存在 → 格式合适 → 浏览器运行。
5. **[项目图片] 失败信号与实例状态裁切**：一边是“无报错”，一边是最终顺序断言。

## Deck.gl：失败如何变成下一轮搜索

### 背景

需求是让地图中的图标持续旋转，同时保持可拾取、控制 CPU 工作、避免每帧重建无关图层，并产出多种独立 HTML 路线。早期生成的 HTML 看起来完整，页面也能打开，但关键目标行为没有成立。

Deck.gl 案例不用于教授某个 accessor 或 shader 语法，而用于展示：生成失败后，Codex 怎样从“再改一次”切换到文档、目标版本源码、相邻实现和真实浏览器构成的证据链。

### 可见问题

- “页面能打开”掩盖了核心动画没有正确发生；
- 公开文档可能描述当前 API，却未必解释目标版本内部转换；
- 静态代码看起来合理的 shader 写法，在真实运行时发生链接错误；
- 单张截图不能证明持续旋转；
- 只验证动画变化，又不能证明变化来自目标 Deck.gl 对象；
- 多条实现路线在正确性、侵入性、性能和版本耦合上不同。

### AI行动

1. 从需求中提取版本、PNG、picking、性能、图层隔离和“不能只靠截图”等硬约束；
2. 将“没有旋转”拆成对象边界、数据语义、生命周期、版本接口和非功能验收；
3. 用模型知识提出多个竞争假设，但不直接把它们当结论；
4. 查官方 API 和生命周期文档确认公开契约；
5. 查目标版本源码确认内部角度处理和接口形式；
6. 设计三条生产候选与一条诊断基线，让它们共享同一组观察指标；
7. 先用结构测试锁定固定版本、必要参数和诊断钩子；
8. 在真实浏览器运行，读取像素变化、picking、初始化次数、暂停状态和控制台；
9. GPU 路线失败后，根据错误继续查同版本官方扩展源码，修正并重跑；
10. 将最终路线、失败范式和适用条件写入复盘。

### 关键转折

真正的转折不是发现某个具体字段，而是停止把“页面不转”当作一个搜索词。它被重写成五类信息缺口，每类进入不同证据。

第二次转折来自浏览器。结构测试已经通过，真实 WebGL 仍然失败。错误将搜索范围从“如何写 shader 动画”缩成“这个版本的官方扩展怎样声明同类参数”。

第三次转折是验证设计：旋转不能靠截图证明，于是需要随时间变化的信号、目标对象拾取和静态图层初始化计数共同支撑。

### 工程产物

- 三条候选路线和一条诊断基线；
- 固定版本 HTML 与结构测试；
- 像素、picking、初始化、暂停和控制台运行报告；
- 对当前架构的条件性建议；
- 失败 shader 范式与升级风险记录。

### 可讲细节

- 文档告诉你公开契约，同版本源码告诉你实现，浏览器告诉你在当前环境是否成立；
- 相邻官方实现往往比网上教程更接近当前版本；
- 运行时错误是高质量查询生成器；
- 多路线实验的价值不是炫技，而是让正确性、侵入性和维护成本可比较；

## 案例之间如何避免重复

| 案例 | 只保留的中心动作 | 不重复展开 |
|---|---|---|
| B747 | 从稀有代码、术语和数字指纹找到专业资料 | 不重复讲完整验证流水线 |
| WPS | 从多个轮子拆取局部资产并翻译到宿主 | 不重复解释所有项目选择细节 |
| Web Excel | 人给比较标准，AI 扩大候选并建立同任务实验 | 不做库产品发布会 |
| Deck.gl | 错误生成新查询，目标版本源码与运行时裁决 | 不教具体 API |
| ECharts | 当前安装版本胜过泛化记忆 | 不猜字段和版本 |
| 飞机建模 | 资料进入可编辑资产，视觉仍需观察 | 不讲完整 Three.js 页面 |
| Dice | 纵向切片与长期负知识 | 不讲游戏规则 |
| Tabloom | 反馈持续产生信息缺口 | 不讲 Chrome API 清单 |
| 大话骰视觉 | 视觉失败必须看见 | 不做模型排名 |
| B站 | 视频只是候选材料与关键词入口 | 不讲完整下载工具链 |

全量稿允许案例互相回响，但同一背景只完整讲一次。后续再次出现时，直接引用观众已经见过的画面或判断。
