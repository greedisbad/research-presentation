# 《AI 辅助技术调研实践》口播反馈重写设计

## 目标

基于 `口播.txt` 重写逐页演讲稿。新稿不预设页数，由真实故事和信息密度决定；每页必须承担一项明确职责：真实事实、故事转折、可迁移方法或必要过渡。

旧稿 `37-全量逐页演讲稿.md` 保留作为素材，不在其上直接删改。

## 核心叙事

这不是一堂工具清单课，也不是抽象的“AI 搜索方法论”。它是一组亲历项目：我遇到了什么问题，AI 去哪里找了什么，人补充了什么现场信息，结果如何被验证，最后留下了什么可以复用的能力。

外层仍采用六幕，但主体改为项目故事：

1. 用原文段子开场，迅速进入 WPS；
2. WPS：多个开源项目各借一部分；
3. B747：沿图片、罕见术语和官网追到可建模资料；
4. Web Excel、ECharts、Deck.gl：分别承担候选比较、停止猜字段、源码与运行验证；
5. Dice、飞机建模、Tabloom：展示 Codex 当前能力，再拆解它为何能做到；
6. 把 Codex 的行动方式迁回公司小模型，并落到项目记忆和人的责任。

## 写作规则

- 一个项目集中讲完整，其他位置最多用一两句回扣。
- 页面标题优先写认知转折或所得经验，项目名作为副标题或上下文。
- 口播中的项目细节默认保留；只删除明确要求删除、与主题无关或完全重复的内容。
- 原文段子保持文字不变，视觉上再处理成社交媒体截图，不扩写解释。
- B 站转写只作为一次拓宽资料入口的尝试，回应课程介绍，不升级为主案例。
- B747 控制在 2–3 页；展示起点、检索链和工程结果，不展开认证级几何细节。
- WPS 不讲 adapter、坐标工具和 Prompt 下沉，重点讲候选项目的局部复用、WPS/Word 文档差异和失败记录。
- Web Excel 展示需求条件、六个同题 HTML 和场景化结论；不做库产品发布会。
- ECharts 保留公司项目口述属性；版本和字段必须标清证据边界。
- Deck.gl 后置，只讲一条代表路线及人发现的“后台补转”问题；四条路线放备份材料。
- 编译、lint、测试、Console、浏览器操作和截图只集中讲一次完整闭环。
- 项目文档、Skill、架构边界和 Commit Message 只集中讲一次长期记忆。
- 不替听众罗列大量 AI 内部注意事项；只保留对人有启发、能迁移到小模型的行为。

## 事实边界

- 用户亲历但无公开材料的公司案例，以第一人称口述，不伪造代码或运行截图。
- `showMinLabel` 在正式稿中只能写成经核验的 ECharts 字段；若无法证明版本差异，不声称它只属于某一版本。
- B747 公开资料可用于建模和预判，不能替代航司内部 W&B / Cargo Loading Manual。
- Dice、飞机建模和 Tabloom 的视觉效果证明 Agent 能产出和迭代，不证明工程精度或普遍模型排名。
- 模型名称若用户记忆与可核验记录不一致，用“当时使用的较强 Codex 模型”等稳健表述。

## 新稿格式

每页包含：

- 页面标题
- 页面任务
- 画面建议
- 页面文字
- 完整口播
- 证据与边界（仅在必要页面出现）

新稿是“全量可删减母稿”，但不靠空泛总结凑页数。后续 HTML 再从中选择现场版页面。

## 完成标准

- `口播.txt` 中所有明确指令都有落实位置；
- 所有非指令型项目详情均已吸收，或因重复/无法确认而在审计表中说明；
- 各项目故事可独立讲清“问题—行动—转折—结果—所得”；
- 页与页之间有自然因果，不靠抽象口号衔接；
- 删除任一页都会损失一个事实、转折或方法。
