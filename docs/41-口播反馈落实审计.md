# `口播.txt` 反馈落实审计

## 用途

本文件回答两个问题：口播中的要求去了哪里；哪些内容因重复、偏题或证据不足没有进入主稿。它不是演讲内容。

## 明确删除或合并

- “让模型说语义，让工具负责坐标”：偏离搜索、筛选与结构化整理主线。
- “Prompt 反复失效就把规则下沉”：有工程价值，但本次不再作为独立观点。
- WPS 双 adapter 的技术实现：留在备份资料，不进主稿。
- “症状不是查询”“当前文档不能替代目标原版”等抽象独立页：相关含义已进入 ECharts、Deck.gl 项目故事，不重复立页。
- “按钮没报错不代表业务正确”“结论不是排行榜”等独立页：已分别并入 Web Excel 的真实状态断言和场景化结论。
- B747 的完整 contour、构型冲突和几何表：主讲只保留搜索路径及资料边界。
- Codex 工作环境逐项清单：压缩成上下文、工具、反馈、隔离、记忆五部分。

## 事实纠正与不确定项

1. Apache ECharts 官方 FAQ 明确：`axisLabel.showMinLabel` 与 `showMaxLabel` 自 3.5.2 起就已支持。因此新稿不能说 4.9.0 没有该字段，也不能把解决过程简单归因于“6.0 新增字段”。更稳健的表述是：项目配置、轴类型、配套选项或记忆中的写法与当前安装版本不匹配；查看本地定义和实际运行才停止猜测。
2. Deck.gl 四条路线和 9.1.12 版本有本地复盘支撑；“后台回来后补转”来自用户亲历，但当前文档未把它绑定到具体文件，因此稿中只说“其中一条候选路线”。
3. 用户口述中的 GPT/Codex 模型编号不承担论证。稿中优先使用“当时较强的 Codex 模型”，避免把一次项目差异伪装成严格模型对照实验。
4. Dice 的提交记录能证明 KayKit 资产、动画、截图和浏览器验证；早期具体使用 Claude/DeepSeek 的情况按用户回忆口述，不声称可由 Git 历史完整证明。
5. WPS 项目“缺少可用文档”改写为“目标环境的资料不完整、对象行为与相邻生态并不完全一致”，避免绝对化。

## 覆盖结论

口播中具有项目事实性质的内容均已进入新稿或在本审计中解释未采用原因。新稿没有继承旧稿的 50 页目标，也没有把被删页面换成新的抽象口号。
