# 企业内部资料交给 AI 调研前的治理清单

“企业产品默认不用于训练”只回答了一个问题，不能推出零留存、无人访问、没有缓存、不会跨区处理或所有功能都受同一策略覆盖。真正的检查单位应是：具体产品 × 具体功能/端点 × 租户配置 × 合同版本 × 数据类别。

## 红黄绿资料分类

这是一份组织策略模板，不是 NIST 规定的固定颜色。

| 等级 | 示例 | 默认处理 |
|---|---|---|
| 绿：公开 | 公开网页、标准、开源代码、合成样本 | 可进入批准的研究工具；仍视为不可信内容，不自动执行附件 |
| 黄：内部 | 内部代码、设计稿、流程、低敏会议转写 | 仅用获批企业租户/API；最小字段、脱敏、RBAC、审计、人工复核 |
| 红：机密/受监管 | 密钥、客户原始数据、身份/健康/支付数据、未公开财务人事、法律特权材料 | 默认不外发；需要数据所有者及安全/隐私/法务特别批准，优先隔离或本地处理 |

## 供应商必须拆开的五个问题

1. **训练**：输入输出是否用于训练或服务改进？默认值和 opt-in/opt-out 是什么？
2. **留存**：提示、输出、文件、向量库、会话、滥用日志分别保存多久？
3. **人工访问**：谁能因支持、安全或滥用审查访问，是否 JIT、审批并留痕？
4. **地域**：推理、存储、日志、备份和子处理方分别在哪些地域？
5. **派生状态**：缓存、微调产物、索引、工具日志和备份如何删除？

OpenAI 当前企业资料说明企业产品与 API 默认不使用业务数据训练模型；其 API 数据控制文档同时按 endpoint 区分滥用监控日志和 application state。Anthropic 的组织数据说明也按 API 与能保存会话的商业产品区分。因此只能引用精确产品能力，不能笼统说“企业版不保存数据”。

## 上线前问题清单

### 数据与目的

- 是否真的需要完整原文，而非字段子集、摘要或合成数据？
- 输入是否完成公开/内部/机密/受监管分类？
- 脱敏是否同时考虑直接标识符、准标识符和上下文重识别？
- 输出能否重新组合出原始秘密？

### 身份、权限与工具

- 是否使用组织身份、SSO、MFA 和角色授权，而非共享账号？
- Agent 是否只读必要目录，而非整个网盘、仓库和环境变量？
- 搜索、下载、解析、执行、写入、发送是否分离授权？
- 安装、发布、删除和外发是否有确定性门禁或人工确认？

### 留痕与响应

- 能否回答谁、何时、把哪类数据发送给哪个端点，并输出到哪里？
- 是否记录工具调用、权限提升、拒绝事件和人工批准？
- 日志是否防篡改，并对异常下载、外发、权限变化告警？
- 事故发生后能否撤销令牌、隔离 Agent、删除资料并通知责任人？
